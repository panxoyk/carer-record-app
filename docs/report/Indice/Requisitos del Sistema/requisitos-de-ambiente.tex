\subsection{Requisitos de ambiente}

El ambiente de evaluación de Carer-Record debe permitir demostrar las capacidades comprometidas para V4 sin utilizar datos clínicos reales. La solución combina una aplicación móvil, servicios de persistencia y control de acceso, una fuente hospitalaria simulada y procesamiento local para las capacidades asistidas.

\subsubsection{Dispositivo móvil}

El dispositivo debe ejecutar la aplicación y, para las funciones de dictado y asistencia de redacción, disponer de los recursos necesarios para ejecutar localmente los modelos seleccionados. El audio de dictado permanece en el dispositivo; no se envía audio a servicios remotos.

\subsubsection{Servicios de aplicación}

La aplicación utiliza Flutter y servicios Supabase para identidad, persistencia y acceso a datos, con políticas RLS como autoridad de autorización. Las notas propias confirmadas pueden persistirse en el backend de Carer-Record; esto no constituye escritura en la FCE. El ambiente debe separar configuración y secretos de forma apropiada.

\subsubsection{Persistencia y archivos}

Los datos estructurados deben conservar sus controles de acceso y procedencia. Los artefactos temporales del procesamiento local deben eliminarse según la política de retención aplicable. La información importada de fuentes hospitalarias y las notas propias de Carer-Record deben poder distinguirse.

\subsubsection{Datos de prueba e interoperabilidad}

La demostración académica utiliza datos sintéticos y HAPI FHIR R4 ejecutado mediante Docker como fuente simulada para la integración hospitalaria. Se demuestra un subconjunto FHIR R4; la conexión con infraestructura hospitalaria real y su certificación institucional quedan fuera del alcance.
