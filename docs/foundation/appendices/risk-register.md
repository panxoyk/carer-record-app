# Registro de riesgos

## Escala

- Probabilidad: Baja, Media, Alta.
- Impacto: Moderado, Alto, Crítico.
- Prioridad P0: bloquea el corte o uso de datos; P1: debe mitigarse antes de cerrar el corte; P2: seguimiento.
- El responsable indicado es un rol propuesto, no una asignación confirmada.

## Riesgos retirados

| ID     | Riesgo                                                                                         | Motivo del retiro                                                                                                                                                   | Evidencia                                                                                                                      | Retirado   |

| RK-028 | El audio crudo de hitos persiste en el bucket privado sin política de retención ni eliminación | ADR-016 retira la provisión de audio almacenado: no existe bucket, columna ni política capaz de transportar audio, así que no queda retención de audio que gobernar | `supabase/migrations/20261012010000_context_note_local_transcription.sql` y `supabase/tests/context_notes_milestones.test.sql` | 2026-10-12 |

Si una necesidad futura vuelve a exigir persistencia de audio, RK-028 se reabre con evidencia y una ADR nueva; no se reintroduce el bucket por extensión de ADR-015.

La evidencia local de fase 5 conserva estos límites: EXPLAIN estimado prueba únicamente indexabilidad/planificación sobre seed pequeño, no runtime RLS ni selectividad productiva; la carrera del último Administrador entre dos sesiones aún no tiene prueba determinista. La integración HTTP restablece el proyecto Supabase local desechable antes/después, incluyendo historia/auditoría sintética; no borrar esas filas manualmente ni usar el script contra estado remoto/compartido.

## Riesgos aceptados temporalmente en el baseline

- La matriz de permisos es estática. Se acepta solo para datos sintéticos y lectura actual, respaldada por pgTAP (`supabase/tests/patients_rls.test.sql:56-130`).
- La función de resumen devuelve 501 (`supabase/functions/clinical-summary/index.ts:17-18`); no se considera una degradación silenciosa porque la capacidad no está entregada.
- Los tests Edge son estáticos (`package.json:21-26`). Se acepta mientras no existan nuevos flujos privilegiados; V2/V5/V6 requieren tests HTTP.
- El RUT completo llegaba al cliente en el baseline histórico; Flutter actual no lo solicita ni lo presenta. No habilitar identificadores completos sin nueva decisión y contrato.

## Revisión

Revisar el registro al iniciar/cerrar cada corte, cambiar proveedor/modelo, introducir una categoría de datos, modificar permisos o descubrir un incidente. Cerrar un riesgo requiere evidencia, no solo completar una tarea. Los riesgos residuales permanecen visibles y se aceptan por un responsable identificado; en este prototipo, la ausencia de ese responsable bloquea datos reales.
